# 实现约定

个人本地应用，Node.js 标准库 HTTP 服务，前端使用原生 ES 模块，数据存入 data/store.json 并原子替换。仅监听 127.0.0.1。

任务保留计划日期；当日期早于今天且未完成时，在今日列表展示为顺延。完成时间决定成果归属。打卡按每日独立记录。同一周以周一日期标识，跨月周归属周一所在月份。统计仅计算选定期间，任务完成率以计划日期归属计算。

节点：1. 基础服务与数据模型；2. 记录、分类和成果；3. 统计、分层复盘与 Markdown 导出；4. 验证与使用说明。

参考：https://github.com/cockpit-project/cockpit 。借鉴模块化 Web 工作区，不依赖 Cockpit 的 Linux 管理服务。

## 事项执行与成果查询

- `date` 为原计划日期；`started` 是选填的实际执行开始日期，完成时必填；`done` 为完成日期或 null。跨月事项按 `done` 所在月查询，实际耗时全额计入完成期，不按日期跨度平摊。
- `minutes` 保留原存储字段，统一用整数分钟；界面拆分小时、分钟输入。最大为 10000 小时 59 分钟。日期跨度和实际投入互相独立。
- `progress` 为 0–100 整数。已完成为 100，未完成必须低于 100。打卡的进度由完成状态决定，界面不显示进度输入。`previousProgress` 保留完成前进度，用于撤销完成。
- `subtype` 为归属事项主类型的子类型名；`subtypes` 保存 `{category, name}` 目录，选项也兼容从旧事项推导。更换主类型会清空当前子类型，避免沿用其他主类型下的选择。
- `milestone` 和 `milestoneNote` 为里程碑标记和备注。已完成查询默认本月，月份、主类型、子类型、仅里程碑采用 AND 组合；子类型可查询“未分类”。
- `public/task-model.js` 集中处理兼容、耗时转换、状态校验和筛选，供页面和服务复用。`public/task-view.js` 提供记录、完成对话框和成果筛选界面。
- 服务写入按队列顺序原子替换文件。测试通过 `DATA_DIR` 使用独立临时目录，不触碰个人记录。浏览器功能验证也使用独立目录和端口。
