# 实现约定

个人本地应用，Node.js 标准库 HTTP 服务，前端使用原生 ES 模块，数据存入 data/store.json 并原子替换。仅监听 127.0.0.1。

新事项创建当天自动开始、完成当天自动结束，未完成和中断事项次日继续可见。完成时间决定成果列表的月份归属；实际用时按记录日期统计，包括未完成事项。打卡按每日独立记录。同一周以周一日期标识，跨月周归属周一所在月份。统计仅计算选定期间，任务完成率以开始日期归属计算。

节点：1. 基础服务与数据模型；2. 记录、分类和成果；3. 统计、分层复盘与 Markdown 导出；4. 验证与使用说明。

参考：https://github.com/cockpit-project/cockpit 。借鉴模块化 Web 工作区，不依赖 Cockpit 的 Linux 管理服务。

## 事项执行与成果查询

- `date` 为兼容旧记录保留；新记录的 `date` 与 `started` 均由创建当天自动赋值，`done` 在完成时自动设为当天（否则 null）。表单不能改写执行日期。撤销完成保留开始日期和用时，再完成时采用新的完成日。
- `timeEntries: [{date, seconds, legacy?}]` 是每日实际用时的事实来源，日期唯一；`minutes` 是累计秒数向下取整的兼容字段。小时/分钟仅用于修正单日总时长，保存时替换该日而非重复累加。修正日期限定在执行范围内且不晚于今天，手填单日上限 24 小时。
- `activeTimer` 保存运行中的 ISO 时间戳，刷新或服务重启后仍可还原累计。暂停、中断、完成或切换事项时，将计时间隔按本机时区的午夜拆分，写入每日记录，清空计时起点。虚拟读取计时不修改存储，防止重复累计。客户端和服务限制同时只有一个事项计时。
- `status` 为 active / interrupted / completed。中断必填理由，记录 `interruptions: [{at, reason, resumedAt}]`；中断停止计时，恢复保留进度与完整历史且不自动重启计时。已中断事项须恢复后才能完成。
- 旧记录缺少每日明细时，原总分钟数转为单条带 `legacy` 标记的记录，归属原完成日或开始日；不推测真实逐日分布。已存在每日明细时不会再次迁移。统计按每日明细（含运行中计时）汇总，成果列表仍按完成月份筛选并显示累计用时。
- `progress` 为 0–100 整数。已完成为 100，未完成必须低于 100。打卡的进度由完成状态决定，界面不显示进度输入。`previousProgress` 保留完成前进度，用于撤销完成。
- `subtype` 为归属事项主类型的子类型名；`subtypes` 保存 `{category, name}` 目录，选项也兼容从旧事项推导。更换主类型会清空当前子类型，避免沿用其他主类型下的选择。
- `milestone` 和 `milestoneNote` 为里程碑标记和备注。已完成查询默认本月，月份、主类型、子类型、仅里程碑采用 AND 组合；子类型可查询“未分类”。
- `public/task-model.js` 集中处理兼容、耗时转换、状态校验和筛选，供页面和服务复用。`public/task-view.js` 提供记录、完成对话框和成果筛选界面。
- 服务写入按队列顺序原子替换文件。测试通过 `DATA_DIR` 使用独立临时目录，不触碰个人记录。浏览器功能验证也使用独立目录和端口。
